# Stock Investment - AI 投資顧問 v1.0

依照 `AI_投資顧問專案規劃書_v1.0.pdf` 實現的 v1.0：從個人持股 Excel 匯入資料，抓取即時股價，產出投資組合分析報告。

## 專案管理

使用 `uv` 進行專案與虛擬環境管理。

```bash
uv sync
```

**Python 版本鎖定在 3.13**（`.python-version` / `requires-python = ">=3.13,<3.14"`）：因為凱基 `kgisuperpy` API 套件目前只提供 Python 3.9–3.13 的預編譯執行檔，尚未支援 3.14，所以本專案暫不使用 3.14。

## 資料來源

`個人持股明細.xlsx`：股票代號、名稱、持股股數、平均成本。名稱已依代號自動填入（見 `fill_names.py`）。

## 使用方式

### 命令列報告

```bash
uv run python main.py
```

輸出投資組合明細、績效、個股基本面、風險評估、加減碼建議、每月追蹤重點。

### 網頁儀表板

```bash
uv run uvicorn app:app --reload
```

啟動後開啟 http://127.0.0.1:8000 查看報告網頁版。

執行 `main.py` 會將最新報告同步覆寫儲存至專案根目錄的 `投資報告.md`（Markdown）與 `投資報告.xlsx`（Excel，八個工作表對應八大區塊），做為固定格式的個人投資檔案。也可分別執行 `uv run python report.py` 或 `uv run python excel_report.py` 只產生其中一種格式。

專案內建 7 個 Claude Code 技能（快速指令觸發詞、對應模型）整理在獨立文件 [`技能清單.docx`](技能清單.docx)。
新增／修改 `.claude/skills/*/SKILL.md` 後，執行 `uv run python generate_skills_doc.py` 可重新產生這份文件，
不需要手動編輯 Word 檔。

## 模組說明

- `portfolio.py`：核心邏輯（讀取持股、以 yfinance 抓取即時股價與基本面、投資組合分析、風險評估、再平衡檢查、產業配置、每月定期定額建議）。
- `report.py`：組合 `portfolio.py` 的分析結果，產出固定格式的 Markdown 投資報告（`投資報告.md`）。
- `excel_report.py`：將相同的分析結果輸出為 Excel（`投資報告.xlsx`，八個工作表）。
- `pdf_report.py`：將相同的分析結果輸出為 PDF（`投資報告.pdf`，橫向 A4、標楷體、內文 14pt 以上），供 Email 附件使用（比 Markdown 檔更適合直接在信箱／手機開啟閱讀）。
- `main.py`：命令列報告輸出，並同步寫入 `投資報告.md`、`投資報告.xlsx`。
- `app.py`：FastAPI 網頁儀表板。
- `fill_names.py`：依股票代號填入名稱的一次性工具腳本。
- `kgi_client.py`：凱基證券 SUPER PY API 連線包裝（僅報價與庫存查詢，**不含下單功能**）。
- `test_kgi_connection.py`：凱基 API 連線測試腳本，需先設定 `.env`。
- `market_data.py`：v4.0 月營收、財報、重大訊息、新聞、大盤指數、三大法人買賣超、融資融券、董監／大股東持股、資產負債表、營益分析、股利分派（全部免費公開資料源，不需金鑰）。
- `technicals.py`：技術面指標（月/季/年線、RSI、KD、MACD、布林通道、ATR、支撐壓力、量能），用 yfinance 歷史股價自行計算。
- `market_environment.py`：市場環境（VIX、費半、那斯達克、美元指數、台幣匯率、台積電 ADR、NVDA/AMD/INTC），yfinance 免費抓取。
- `scoring.py`：AI 綜合評分引擎，六構面加權評分（Investment Score）＋獨立 Risk Score，換算成🟢🟡🟠🔴四色行動建議，含極端虧損股節流（`alert_state.json`）。詳見下方「AI 綜合評分與行動建議」章節。
- `candidate_watchlist.py`：潛力新標的觀察，從人工整理的優質股/ETF候選池篩出目前未持有、評分較高的標的（高價股/低價股各3檔）。詳見下方「潛力新標的觀察」章節。
- `notify.py`：v5.0 Email 通知（SMTP，預設 Gmail）＋ LINE 通知（Messaging API，Broadcast）。
- `daily_report.py`：v5.0 每日排程入口，產生報告並寄送 Email＋LINE（供 Windows工作排程器呼叫）。
- `sector_rotation.py`：短線類股輪動掃描（依 3-7 天動能排名族群與個股，搭配均線給買賣參考區間；RSI過熱排除）。
- `spouse_report.py`：把短線輪動觀察獨立寄給太太（不含使用者本人持股/金額），BCC 一份給使用者。
- `microstructure.py`：盤中開盤強弱評分（開盤溢價率／委買委賣量／量能確認），僅供太太的短線輪動觀察使用。
- `spouse_intraday_check.py`：盤中警示（09:35／11:30 排程），寄給太太的盤中強弱更新。
- `rotation_tracking.py`：短線輪動預測的事後驗證追蹤（記錄預估報酬率，天數到期後拿實際股價比對落差）。
- `generate_skills_doc.py`：讀取 `.claude/skills/*/SKILL.md` 重新產生 `技能清單.docx`，新增/修改技能後手動重跑。
- `專案進度.md`：專案至今的執行步驟紀錄。

### 疑難排解：`CheckCAComponent failed` / `CoCreateInstance() fail`

若執行 `test_kgi_connection.py` 出現這個錯誤，代表**線上 API 申請**與**本機憑證元件安裝**是兩件不同的事——這台電腦還沒安裝凱基的「憑證元件（Servisign）」，TradeCom 沒辦法透過 COM 介面驗證憑證。解法：

1. 前往 https://event.kgi.com.tw/service/ServisignExplanation.htm 下載並執行 `KGICGCAPIATL2ADPTSetup.exe`，依指示安裝（過程中若跳出防火牆提示請允許存取）。
2. 安裝完成後重新啟動電腦。
3. 重新執行 `uv run python test_kgi_connection.py`。

若仍失敗，可改走手動註冊方式：下載 `TradeComExample_TSEC.zip`（https://www.kgieworld.com.tw/UpLoadFiles/eUpLoadFile/TradeComExample_TSEC.zip）解壓縮後，以**系統管理員身分**開啟命令提示字元，切換到解壓縮路徑的 `bin\Release`，執行 `regsvr32 KGICGCAPIATL2x64.dll`，看到「DllRegisterServer 成功」才算完成。這一步需要系統管理員權限與 GUI 安裝流程，請您本機自行完成；我這邊無法透過終端機直接幫您安裝或註冊系統元件。

### 疑難排解：憑證與帳戶權限都確認無誤，卻卡在「連線超時，請檢查網路狀態」

`test_kgi_connection.py` 執行到能取得 ranking token（`Successfully obtained ranking token`），代表憑證元件與帳密都正確；但接著若卡在：

```
[系統訊息] 路徑設定完成（環境=虛擬下單環境）。
請確認該賬戶權限
[系統訊息] 連線超時，請檢查網路狀態。
AttributeError: 'TradeCom' object has no attribute 'FIsLogon'
```

且已致電凱基客服確認該身分證字號的帳號已開通 SUPER PY API／模擬交易權限，此時問題多半出在**網路連線層**，而非憑證或帳戶設定：

- Ranking token 走的是一般 HTTPS，但實際交易連線（TradeCom）走的是另一組專屬連接埠，**企業網域網路的防火牆很常只放行前者、擋掉後者**。
- **排除方法（已實測驗證）**：換一個非公司網路環境（例如手機熱點）重新執行 `uv run python test_kgi_connection.py`。**注意：若電腦同時連著公司網路（有線或 Wi-Fi）跟熱點，Windows 預設會選路由 Metric 較低的介面**（通常是公司的有線網路），熱點不會被實際使用，必須把公司網卡**停用**（設定 → 網路和網際網路 → 該網卡 → 停用；或系統管理員身分執行 `Set-NetIPInterface -InterfaceIndex <公司網卡Index> -InterfaceMetric 9999` 調降優先權），確認 `Get-NetConnectionProfile` 只剩熱點那條連線，才是真正乾淨的測試。
- 實測結果：停用公司網卡、純走手機熱點後，連線成功通過（`OnConnected()` / `API 加載完成`），證實是**公司防火牆擋掉了 TradeCom 連線**。需洽凱基 API 客服取得需放行的網域／IP／連接埠清單，轉交公司 IT 開白名單。
- 附帶一提：連線逾時發生時，`kgisuperpy` 套件本身沒有妥善處理這個例外，會直接對尚未初始化的物件取屬性而丟出 `AttributeError: 'TradeCom' object has no attribute 'FIsLogon'`，這是凱基官方套件的邊界情況未處理好，不是 `kgi_client.py` 的問題。

### 疑難排解：連線層通過後，卡在「CGPureSign... Fail!! ErrorCode = 5010」

網路連線問題排除後（`OnConnected()` 成功），若接著卡在：

```
[Login][CheckCAComponent] ok
[Login][CheckCAInfo]...(身分證字號)
CGPureSign... Fail!! ErrorCode = 5010
[ERROR][Login][CheckCAInfo] faild ... (5010)
```

代表憑證元件本身註冊正常（`CheckCAComponent ok`），但用憑證做簽章驗證（`CGPureSign`）失敗。這是凱基內部專屬錯誤碼，沒有公開文件，可能原因包括本機安裝的 Servisign 憑證跟登入身分證字號不吻合、憑證過期，或憑證綁定的帳號跟目前使用的不同。請致電凱基 API 客服 (02)2389-0088 / 0800-085-005，直接提供「ErrorCode 5010」詢問。

## 已實現的 v1.0 功能

固定格式投資報告包含八大區塊：

1. 投資組合總覽（總成本、總市值、總報酬率、各股市值佔比與成本佔比）
2. 個股分析（產業別、本益比、EPS、法人目標價與評等）
3. 合理買點（近 52 週區間 + 法人目標價估算承接區間）
4. AI 綜合評分與行動建議（六構面加權評分＋獨立 Risk Score，換算成🟢加碼買進／🟡持有觀察／🟠分批獲利了結／🔴全數賣出；詳見下方「AI 綜合評分與行動建議」章節）
5. 產業配置建議（產業別佔比與集中度提醒）
6. 風險評估與再平衡（集中度風險、市值佔比對比原始成本佔比的偏移）
7. 每月投資建議（依每月定期定額新台幣 10,000 元，依估值吸引力分配加碼標的；已列入停損觀察的標的不會自動建議加碼）
8. 後續追蹤重點
9. 市場情報：月營收、財報、重大訊息、新聞、法說會排程、三大法人買賣超（v4.0，見下方說明）

另外「一、投資組合總覽」會顯示大盤（加權指數）收盤與漲跌，現價也改用較即時的證交所看盤 API（見下方說明）。

## v4.0：月營收、財報、重大訊息、新聞、法說會排程、大盤指數、三大法人買賣超、即時報價

`market_data.py` 全部使用**免費公開資料源**，不需申請、不需金鑰：

- **月營收**：台灣證交所 OpenAPI `t187ap05_L`（僅涵蓋上市公司）
- **財報重點**（營收、EPS）：台灣證交所 OpenAPI `t187ap06_L_*`（依業別自動合併一般業／金控／證券期貨／保險／金融業）
- **重大訊息**：台灣證交所 OpenAPI `t187ap04_L`（上市公司每日重大訊息公告）
- **新聞**：Google 新聞 RSS（依股票名稱查詢，中文財經新聞，涵蓋 ETF／上櫃股）
- **法說會排程**：公開資訊觀測站（MOPS）「法人說明會一覽表」（`mopsov.twse.com.tw`），涵蓋上市／上櫃／興櫃；顯示每檔持股「今天以後最近一場」法說會的日期、時間、地點。
- **大盤指數**：台灣證交所 OpenAPI `exchangeReport/MI_INDEX`，取「發行量加權股價指數」收盤與漲跌。
- **三大法人買賣超**：上市個股用證交所官方 `www.twse.com.tw/rwd/zh/fund/T86`（可拆分外資／投信／自營商）；上櫃個股用櫃買中心 `www.tpex.org.tw/www/zh-tw/insti/dailyTrade`（欄位無法明確拆分，僅取合計）。
- **即時股價**：改用證交所官方看盤 API（`mis.twse.com.tw`），比 yfinance 的延遲快照更即時；抓不到時仍會 fallback 回 yfinance 的價格。

**已知限制**：
- 月營收／財報／重大訊息僅涵蓋**上市（TSE）公司**（本專案目前持股皆為上市公司，故無影響）；若未來持有上櫃（TPEx）個股，這幾項會查不到資料（新聞、法說會排程、三大法人買賣超不受此限制）。ETF（如 0050、00878 等）本身也不會有月營收／財報／法說會資料，屬正常現象。
- 台灣證交所 OpenAPI 資料為當日／最新一期快照，非歷史查詢。
- 三大法人買賣超與即時股價都是「近即時」的官方公開看盤資料，不是逐筆委託成交明細，也不是券商帳戶內的即時報價串流。
- 上櫃三大法人買賣超因櫃買中心 JSON 欄位重複、無官方欄位標籤，只能取三大法人合計數，無法拆分外資／投信／自營商。
- 法說會排程僅顯示公司已公告、當年度尚未召開的場次；若公司尚未公告下一場，會顯示為無資料。

## 個人短期目標追蹤

使用者於 2026-07-25 設定的個人目標，日期常數（`GOAL_BASELINE_DATE`／`GOAL_TARGET_DATE`）寫死在
`portfolio.py`，但真實總資產數字（`GOAL_BASELINE_VALUE`）改從 `.env` 讀取（**不寫死在程式碼裡**，
準備上傳 GitHub 時才發現這樣會把真實淨資產永久留在 git 歷史紀錄裡，即使之後改掉也清不掉），
`.env.example` 有對應的空白欄位範本。每份報告最前面都會顯示：

- **目標一（獲利）**：一年內累積獲利（總市值−總成本，含新增定期定額投入的部位）達到基準時的總市值
  （即設定當下的實際總市值，實際金額見個人 `.env` 的 `GOAL_BASELINE_VALUE`，不寫在文件裡）。
  用「總市值−總成本」而不是「總市值」當獲利指標，是因為新增的定期定額投入會虛增總市值，
  但不會虛增這個成本基礎的獲利數字。
- **目標二（下限）**：期間內任何時候的總市值都不低於基準總市值——不是「賺到目標」才算數，過程中也
  不能破底。
- 每份報告都會算「進度是否符合預期」（依已過天數比例回推應有的累積獲利門檻）與「是否已跌破下限」，
  達不到會標示 ⚠️。

## AI 綜合評分與行動建議

取代原本單純「獲利/虧損門檻」的停利停損建議，改用六構面加權評分＋獨立 Risk Score，最終只給四種結論：
🟢加碼買進／🟡持有觀察／🟠分批獲利了結／🔴全數賣出。核心精神：AI 的目標不是預測股價，而是回答
「該不該採取行動」，且一定要結合股票本身的評分與使用者目前的持股狀態（成本、損益率、佔比），
不能只看股票。

**六構面權重**：基本面30%／成長性20%／籌碼面15%／技術面15%／估值10%／市場環境10%。每個子項目
正規化到 0-100 分；缺資料的子項目**不計 0 分**，而是把該類別權重按比例分給其餘可用子項，並回傳
「資料覆蓋率」——覆蓋率低於 50%（常見於 ETF，因為 ETF 沒有基本面/董監持股資料）時，訊號會標註
「僅供參考」，不會用不完整的資料假裝出高信心的結論。

**特殊規則**（對應使用者實際持股情境調整過）：
- **極端虧損（≤-70%）降低提醒頻率**：不會每天重複提醒「建議停損」，除非新聞命中重大利多／利空關鍵字
  （FDA核准、被收購、下市、減資、查核意見等），或 Investment Score 顯示有回升機會（標記⭐重點追蹤）。
  用 `alert_state.json`（執行期產生，不上傳）記錄每檔持股上次提醒的日期，7 天內同訊號就不會出現在
  Email／LINE 摘要（完整報告仍會列出）。
- **獲利但法人持續看好，不盲目賣出**：獲利達 +50% 時，若法人評等買進／目標價仍高於現價，建議續抱
  並附上實際的法人目標價數字；現價已超合理價 20% 才建議分批獲利了結。
- **禁止追高**：現價距法人目標價 ≥20% 直接標記「不建議追價」並說明距離。
- **加碼六條件**：基本面未惡化／長期趨勢向上／法人未大幅調降目標價／EPS未惡化／籌碼未崩壞／技術面
  接近支撐，六項全符合才會建議逢低加碼。

**個人化設定**（`portfolio.py`，比照 `MONTHLY_INVESTMENT` 寫死，要調整直接改常數）：
`AVAILABLE_CASH`（可投入現金）／`RISK_TOLERANCE`（風險承受能力）／`INVESTMENT_HORIZON`（投資期限）。

**已知略過的項目**（沒有免費、不需金鑰的可靠資料源，用既有新聞機制間接帶過，不做成結構化欄位）：
DCF（現金流折現，本身就是假設驅動、容易產生假精確的數字）、FOMC 會議時程／CPI／利率、台指夜盤。

## 薪資現金流投資人系統（每月投資建議）

使用者定位自己是「薪資現金流投資人」：每月固定投入約 1 萬元、不借貸不融資、長期持有 5-20 年。「七、每月投資
建議」不再是單純的估值排序，而是：

- **現金流優先**：本月可投資金額＝每月固定投入＋現金流結餘（股利／已實現獲利／手動存入，來自
  `個人持股明細.xlsx` 的「現金流」分頁，日期／項目／金額／備註，金額正數＝存入現金池、負數＝已投入或提領）。
  結轉上限為 **3 個月投入金額**（`MAX_CARRYOVER_MONTHS`），避免一直等最佳買點而長期空手。
- **優先購買清單集中投入**：依 Investment Score／Conviction Score 排出優先順序，資金**集中在前 1-3 名**
  （`MAX_MONTHLY_FUNDED_CANDIDATES`），不是每檔都買一點。
- **分批買進 4 個 Level**：依現價相對法人目標價／52 週區間，決定本次投入佔預算的比例——
  Level 1 市場正常 20%／Level 2 跌到合理價 30%／Level 3 最佳買點 30%／Level 4 恐慌大跌 20%。
- **等待成本計算**：現價略高於合理價時，比較法人預估的上漲空間 vs 目前的高估幅度，決定「等待反而容易
  錯過行情，可以開始布局」還是「等待成本較低，建議等待拉回」。
- **持股配置上限**：個股最高 25%，大型 ETF 較分散可放寬到 30%（取代原本統一的 30% 集中度門檻）。
- **長期持股信心分數（Conviction Score，1-5 星）**：跟 Investment Score 是不同維度——Investment Score
  回答「現在是不是好買點」（每天可能變動），Conviction Score 回答「這家公司體質好不好、值得長期一直買」
  （相對穩定）。用 ROE、毛利率、負債比、市值規模、是否穩定配息組成量化代理指標，**不是真正的護城河或
  管理品質評估**，僅供參考。

## 潛力新標的觀察（`candidate_watchlist.py`）

原本 `scoring.py` 的六構面評分只分析**目前持有**的股票，使用者發現「都在我的持股裡運算」——完全沒有
「發掘目前沒持有的優質新標的」這塊功能。新增獨立區塊回答這個問題，跟既有持股的「AI 綜合評分與行動
建議」是兩件事：那邊回答「該不該對目前持股採取行動」，這裡回答「還有沒有值得考慮加入的新標的」。

- **候選池是人工整理的清單，不是全市場掃描**：`CANDIDATE_POOL` 收錄約 25 檔台股常見權值股／優質股
  代表（涵蓋半導體、金融、電信、傳產、紡織等多元產業）+ 6 檔熱門 ETF，比照太太 `sector_rotation.py`
  的 `WATCHLIST` 做法。原因：上市櫃合計近 2000 檔，用免費資料源逐檔套六構面評分（財報/技術面/籌碼面
  都要抓）成本太高，全市場掃描不可行。
- **排除目前已持有的標的**，並排除現在追高（現價超過法人目標價 20% 以上）的候選股，不建議現在進場的
  股票不會列入。
- **依股價分「高價股」「低價股」各挑 3 檔**：候選清單依股價排序切成兩半，各組內再依 Investment Score
  取前 3 名，讓不同資金水位都有選項可看，不是清一色權值股。
- **不套用 `decide_signal()` 的持倉判斷邏輯**：候選股沒有成本、`pnl_pct` 必為 `None`，如果直接套用
  既有持股的四色訊號決策，會一律落到「🟡 尚無市價資料」沒有意義。改用新的 `scoring.evaluate_candidate()`，
  只計算六構面評分／Risk Score／Conviction Score，只回答「值不值得列入觀察」，不回答「該不該賣」。
- **獨立區塊列在每日報告**：Markdown（第十節）／Excel（「潛力新標的觀察」分頁）／PDF（第十節）／
  網頁儀表板／Email 摘要都有，跟既有持股分開列，不佔既有報告篇幅太多。

## 盤中開盤強弱觀察（Market Microstructure，僅限太太的短線輪動）

使用者提出一套「開盤溢價率」判斷強弱的規則，經使用者自己審查後明確否定原始的硬性版本（「沒有任何學術
研究支持」「開+6%收+2%隔天-4%太常見了」），改成量能確認的加減分規則。**這只當觀察因子，不是必勝公式**，
且**只用在太太的短線輪動觀察，不影響使用者本人長期持股的月度配置決策**（那是完全不同性質的長期規則）。

- `microstructure.py`：抓開盤價／昨收／盤中高低／累積成交量（證交所 `mis.twse.com.tw` API，含五檔委買委賣量欄位
  `f`／`g`）＋ yfinance 盤中 5 分K（`between_time("09:00","09:30")` 取開盤 30 分鐘最低價）。
  `score_open_premium()` 依三條規則給 0-100 分：
  - 開盤溢價 >5% 且 30 分鐘內未跌破 +3%，量能達 20 日均量 150% → +15（強勢確認）
  - 盤中最高衝上 +7% 但現在剩不到 +4% → -20（疑似獲利了結賣壓／開高走低）
  - 爆量（≥20日均量200%）且站上開盤價 → +10；爆量但跌破開盤價 → -25（爆量黑K警訊）
- `spouse_intraday_check.py`：**盤中資料只有交易時段才有意義，跟其他「一天跑一次」的模組不同**，因此新增
  兩個獨立排程「AI投資顧問_太太盤中觀察_0935」「AI投資顧問_太太盤中觀察_1130」（09:35＝開盤 30 分鐘確認、
  11:30＝盤中觀察），各自寄一封簡短更新給太太（BCC 使用者），跟 05:00 的完整輪動報告分開、互不影響。
  執行前會先用 `microstructure.is_trading_session_now()` 檢查週一~週五／09:00~13:30／即時報價日期是否為
  今天三個條件，**非交易時段（週末、國定假日、尚未開盤或已收盤）直接略過、不寄送**，不會用舊資料湊報告。

**已知限制**：規則型評分，沒有經過統計驗證；量能比對用的是「近 20 日平均日成交量」，不是「歷史同一時段
的正常量」，量能比例僅供粗略參考；集合競價強度、真正逐筆 VWAP 目前沒有免費資料源，未實作。

## 短線類股輪動觀察（給太太的獨立報告）

`sector_rotation.py` + `spouse_report.py`：與使用者本人的長期持股分析完全分開的延伸功能，**不含使用者的持股明細與金額**，內容改成短線類股輪動的參考標的。

**方法論**：
- 依「3-7天平均漲跌幅」（3日與7日報酬率取平均，視為短期動能）幫 `WATCHLIST`（人工整理的常見台股熱門族群代表股，共 11 個族群：記憶體/半導體/AI伺服器/航運/金融/生技製藥/網通/面板/綠能/**重電**/**軍工**）裡的族群排名，取最強的前 5 名（排名1~5）
- 族群內個股同樣依 3-7天動能排序，取前 5 檔（該族群 watchlist 代表股不足 5 檔時，就顯示全部）
- 另外加一份「個股動能 Top5」：不分族群、跨全 watchlist 依動能取前 5 檔個股，再依**股價單價由低到高**重新排序（方便快速比較好入手的標的），同樣排除 RSI 過熱的追高風險股
- 買入區間：5日/10日均線區間（拉回接近均線分批買入）
- 獲利了結區間：近 10 日高點附近
- 預估天數：用近 3 日日均漲幅回推到獲利了結區間大約要幾個交易日，限制在 2~10 天

**重要限制**：這是短線技術面規則型參考，不是價格預測，短線進出風險遠高於本專案其他長期持股建議，不保證獲利。`WATCHLIST` 是人工整理的代表股，非全市場掃描，可能遺漏其他正在輪動的族群。

**寄送方式**：`uv run python spouse_report.py` 寄給 `.env` 裡 `SPOUSE_EMAIL` 設定的信箱，並 BCC（密件副本）一份給使用者自己，收件人看不到使用者也收到副本。已排入每天 **05:00** 的自動排程（跟主報告同一時間，各自獨立寄送）。

**Email 排版（HTML，太太專用）**：股票名稱／代號分別用醒目對比色標示（名稱玫瑰紅、代號寶藍），獲利了結區間的價位用醒目紅色粗體標示（刻意避開綠色——台股慣例紅漲綠跌，用綠色語意會反過來），字體全面加大到 14.5~17px（一般內文 15px、標題 17px、股票名稱代號與獲利了結價位 16px 粗體、免責聲明最小 14.5px），方便手機瀏覽時一眼抓到重點。純文字版仍保留當作收信端不支援 HTML 時的備援。盤中觀察（`spouse_intraday_check.py`）採用同一套配色與字級規則，兩封信視覺一致。

**預測事後驗證與每週彙總（`rotation_tracking.py`）**：每次寄出推薦清單時，把「當下股價／預估報酬率／預估天數」記錄到 `rotation_predictions.json`；下次執行時會自動找出預估天數已到、還沒驗證過的預測，拿實際股價回頭比對，算出「預估 vs 實際」的落差，並嘗試推斷落差原因（預測當下的警訊／同期大盤同步程度／新聞關鍵字偏多偏空／驗證當下的 RSI 與量能，查不到明確外部因素時也會給出「規則本身預測力可能不足」的具體結論，不會停在「原因不明」）。這些驗證結果**不會**出現在太太每天收到的信裡，而是每週五單獨整理成一份彙總 Email 寄給使用者本人（`notify.EMAIL_TO`），由使用者自行判斷要不要據此調整 `sector_rotation.py` 的規則或門檻——這套機制只負責蒐集資料與提供推斷依據，不會自動修改程式。

**背景**：`notify.py` 目前用 `smtplib` 走 SMTP（587埠）寄信，公司網域網路會擋這個埠（但不會擋一般網頁瀏覽用的 HTTPS／443埠，這也是為什麼證交所 OpenAPI、yfinance 這些資料源在公司網路下都抓得到，只有寄信會卡）。若改用 Gmail API（本質是 HTTPS 443 埠的 REST API），理論上能在公司網路下直接寄信，不需要再切換手機熱點。使用者決定先不動 `notify.py`，之後自行實驗，這裡先記錄步驟：

1. 前往 https://console.cloud.google.com/ 建立（或選用既有）專案。
2. 「API 和服務」→「已啟用的 API 和服務」→ 搜尋並啟用 **Gmail API**。
3. 「API 和服務」→「OAuth 同意畫面」→ 設定為「外部」＋測試模式，測試使用者填入自己的 Gmail 帳號（`EMAIL_ADDRESS` 那組）。
4. 「API 和服務」→「憑證」→「建立憑證」→「OAuth 用戶端 ID」→ 應用程式類型選 **電腦版應用程式（Desktop app）** → 下載 `client_secret.json`，放在專案目錄（**務必確認會被 `.gitignore` 排除**，本專案 `.gitignore` 已有廣義 `*.json` 規則涵蓋，但下載後建議手動用 `git check-ignore -v client_secret.json` 再次確認）。
5. 安裝套件：`uv add google-auth google-auth-oauthlib google-api-python-client`。
6. 第一次執行時，程式呼叫 `google_auth_oauthlib.flow.InstalledAppFlow.from_client_secrets_file(...)` 會跳出瀏覽器要求登入並授權，授權完成後會在本機存一份 `token.json`（含 refresh token，同樣要確認被 gitignore），之後重新執行不需要再登入，除非 token 失效或撤銷授權。
7. 把 `notify.py` 的 `send_email()` 改成用 Gmail API：訊息一樣先組成 `email.message.EmailMessage`，但改成 base64url 編碼後透過 `googleapiclient.discovery.build("gmail", "v1", credentials=creds).users().messages().send(userId="me", body={"raw": encoded}).execute()` 寄出，取代原本的 `smtplib.SMTP(...)` 那段。

**取捨**：一次性設定成本較高（要跑 Google Cloud Console 設定＋OAuth 授權流程），換來的是**以後在任何網路環境（含公司網路）都能直接寄信，不用再切換熱點／停用網卡**。
